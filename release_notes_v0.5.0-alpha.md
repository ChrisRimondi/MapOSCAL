## 🚀 Kubernetes Support & Analysis

### **What's New**
MapOSCAL now provides comprehensive Kubernetes manifest analysis, automatically mapping Kubernetes security features to NIST 800-53 compliance controls.

### **Key Features**

#### **Comprehensive Resource Analysis**
- **Deployments & StatefulSets**: Analyzes container configurations, security contexts, and resource limits
- **Services & Network Policies**: Maps network security configurations to compliance controls
- **ConfigMaps & Secrets**: Evaluates configuration management and data protection
- **RBAC & ServiceAccounts**: Analyzes access control and identity management
- **Pod Security Standards**: Automatic detection of security context configurations
- **Persistent Volumes**: Evaluates data persistence and protection mechanisms

#### **Security Control Mapping**
- **Access Control (AC)**: Maps RBAC, ServiceAccounts, and security contexts
- **Configuration Management (CM)**: Analyzes ConfigMaps, resource limits, and configurations
- **System & Communications Protection (SC)**: Evaluates network policies and TLS configurations
- **Contingency Planning (CP)**: Maps backup and recovery configurations
- **System & Information Integrity (SI)**: Analyzes monitoring and logging configurations

#### **Dedicated Analysis Workflow**
```bash
# New Kubernetes analysis command
maposcal k8s-process config.yaml

# Generates standards-compliant OSCAL component definition
# Output: k8s_oscal_component_definition.json
```

### **Example Kubernetes Analysis**
```yaml
# Input: Kubernetes manifests
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-app
spec:
  template:
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 1000
      containers:
      - name: app
        image: nginx:latest
        ports:
        - containerPort: 443
        env:
        - name: API_KEY
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: api-key
```

**Output**: Automatic mapping to controls like AC-6 (Least Privilege), CM-6 (Configuration Settings), and SC-7 (Boundary Protection)

## 🔧 Compliance-Trestle Integration

### **What's New**
MapOSCAL now uses the industry-standard `compliance-trestle` library for generating 100% OSCAL 1.1.3 compliant component definitions.

### **Key Features**

#### **Standards Compliance**
- **OSCAL 1.1.3 Compliance**: Full adherence to the latest OSCAL standard
- **Schema Validation**: Automatic validation using compliance-trestle models
- **Type Safety**: Strong typing and compile-time validation
- **Future-Proof**: Automatic support for OSCAL standard updates

#### **Enterprise-Grade OSCAL Generation**
```json
{
  "component-definition": {

    "metadata": {
      "title": "MapOSCAL Generated Component",

        "uuid": "75dc64b3-5e71-4c95-b730-37d19754b793",
```

#### **Enhanced Validation**

## 🚀 Getting Started

### **Installation**
```bash
pip install maposcal==0.5.0-alpha
```

### **Quick Start**
```bash
# Analyze code and generate OSCAL
maposcal generate config.yaml

# Analyze Kubernetes manifests
maposcal k8s-process config.yaml

# Run comprehensive analysis
maposcal run-all config.yaml
```

### **Example Configuration**
```yaml
title: "Secure Application"
description: "Application with comprehensive security controls"
repo_path: "/path/to/application"
output_dir: ".oscalgen"

# Kubernetes manifests to analyze
k8s_manifests:
  - "k8s/deployment.yaml"
  - "k8s/service.yaml"
  - "k8s/rbac.yaml"

llm:
  provider: "openai"
  model: "gpt-4"
```
